## Design Pattern

### In-Memory Fake Repository
- **Location**: [`src/boardgamerules/db/in_memory.py:11`](src/boardgamerules/db/in_memory.py#L11)
- **Why & How**: Unlike brittle unittest.mock patches that assert how a database driver was called, an in-memory Fake implements the real repository contract (including uniqueness constraints, sorting, and auto-superseding) so service and API tests run in microseconds without Docker.

### Data Mapper Pattern (vs. Active Record / ODM)
- **Location**: [`src/boardgamerules/db/mappers.py:28`](src/boardgamerules/db/mappers.py#L28)
- **Why & How**: Unlike Active Record ODMs (like Beanie or MongoEngine) where domain models inherit from a database Document class and call `await model.save()`, a Data Mapper translates between pure domain dataclasses and raw MongoDB "_id" dicts. This keeps domain logic vendor-agnostic (easy to swap MongoDB for GCP Firestore or InMemory fakes) and testable without a DB.

### Structural Subtyping (Ports & Adapters / Hexagonal Architecture)
- **Location**: [`src/boardgamerules/domain/contracts.py:20`](src/boardgamerules/domain/contracts.py#L20)
- **Why & How**: Using typing.Protocol defines "ports" in the inner domain layer without importing concrete drivers (MongoDB, Qdrant, GCS, Gemini). Any adapter class that implements matching method signatures satisfies the contract automatically without needing class inheritance.

### Runtime-Checkable Protocols (@runtime_checkable)
- **Location**: [`src/boardgamerules/domain/contracts.py:25`](src/boardgamerules/domain/contracts.py#L25)
- **Why & How**: By default, typing.Protocol only exists for static type checkers (PyCharm, mypy) and fails if used with isinstance() at runtime. Decorating with @runtime_checkable allows runtime isinstance(obj, Protocol) checks by verifying that the required method names exist on obj, while static type checkers still enforce full parameter, return, and async coroutine types.

### Interface Segregation Principle (ISP)
- **Location**: [`src/boardgamerules/domain/contracts.py:31`](src/boardgamerules/domain/contracts.py#L31)
- **Why & How**: Instead of forcing every service to depend on a single giant database interface, we split persistence into 4 focused repository protocols (User, GameManual, PendingPdf, UserHistory). The Batch PDF Job only needs PendingPdfRepository + GameManualRepository, keeping mocks tiny.

### Composite Interface Facade
- **Location**: [`src/boardgamerules/domain/contracts.py:77`](src/boardgamerules/domain/contracts.py#L77)
- **Why & How**: Combining the 4 segregated repository protocols into a single composite NoSqlRepository protocol lets the DI container pass one unified database adapter when needed, while individual consumers still type-hint only the narrow sub-protocol they require.

### Domain Exception Hierarchy
- **Location**: [`src/boardgamerules/domain/exceptions.py:6`](src/boardgamerules/domain/exceptions.py#L6)
- **Why & How**: Defining a single base domain exception (BoardGameRulesError) with specific subclasses lets higher layers (like FastAPI exception handlers) map domain failures cleanly to HTTP status codes (e.g., 400, 404, 502) without coupling domain code to HTTP frameworks.

### Immutable State Machine Transition
- **Location**: [`src/boardgamerules/domain/manual.py:57`](src/boardgamerules/domain/manual.py#L57)
- **Why & How**: Instead of mutating self.status in place, transition methods return a new frozen instance via dataclasses.replace(), preserving Command-Query Separation and history safety.

### Value Object & Immutable Entity

- **Why & How**: Using @dataclass(frozen=True) makes domain entities thread-safe, hashable, and predictable: functions cannot secretly mutate shared state as objects pass through the pipeline.

## System Design

### Single-Active-Record Invariant (Auto-Superseding)
- **Location**: [`src/boardgamerules/db/in_memory.py:37`](src/boardgamerules/db/in_memory.py#L37)
- **Why & How**: When a new READY manual is saved for a (game_id, edition), any previously READY manual for that same game and edition (such as an earlier Tier-3 AI fallback) is automatically transitioned to SUPERSEDED so queries never return stale unverified rules.

### UTC Timezone Normalization at Persistence Boundary
- **Location**: [`src/boardgamerules/db/mappers.py:18`](src/boardgamerules/db/mappers.py#L18)
- **Why & How**: MongoDB stores timestamps in UTC but deserializes BSON Date values as timezone-naive datetime objects by default. Attaching UTC at the mapper boundary guarantees domain entities always receive timezone-aware UTC timestamps.

### NoSQL Operator Injection Prevention
- **Location**: [`src/boardgamerules/db/mongo.py:30`](src/boardgamerules/db/mongo.py#L30)
- **Why & How**: In MongoDB, passing a dict like {"$ne": None} as a filter value executes a query operator instead of a literal equality check (CWE-943). Enforcing strict scalar types (str/int) at the repository query boundary blocks operator injection even if upstream validation is bypassed.

### Exception Translation at Infrastructure Boundary
- **Location**: [`src/boardgamerules/db/mongo.py:46`](src/boardgamerules/db/mongo.py#L46)
- **Why & How**: Catching low-level driver exceptions (PyMongoError) and re-raising a domain exception (StorageOperationError) prevents database driver details from leaking into business logic.

### Asynchronous I/O for High-Concurrency LLM Workloads
- **Location**: [`src/boardgamerules/domain/contracts.py:13`](src/boardgamerules/domain/contracts.py#L13)
- **Why & How**: Unlike traditional CRUD apps (where DB queries take ~3ms), AI/RAG workloads wait 2-8 seconds on external LLM generation, embedding APIs, and vector searches. Using async def contracts allows a single GCP Cloud Run container's event loop to serve hundreds of concurrent users waiting on I/O without blocking OS threads or spinning up costly extra containers, and enables parallel I/O fan-out via asyncio.gather().

### Cloud-Agnostic Blob Storage Abstraction
- **Location**: [`src/boardgamerules/domain/contracts.py:132`](src/boardgamerules/domain/contracts.py#L132)
- **Why & How**: Cloud Run containers have ephemeral filesystems. Abstracting PDF file operations behind PdfStorage lets local development use a local directory while GCP Cloud Run Jobs use a Google Cloud Storage (GCS) bucket with zero changes to the batch ingestion logic.

### Content-Addressable Deduplication (SHA-256)
- **Location**: [`src/boardgamerules/domain/validators.py:44`](src/boardgamerules/domain/validators.py#L44)
- **Why & How**: Hashing raw PDF bytes with SHA-256 produces a deterministic 64-char fingerprint. Checking this hash before chunking or embedding guarantees the same rulebook PDF is never ingested twice, even when uploaded under different filenames or fetched from mirror URLs.

### Path Traversal Defense-in-Depth
- **Location**: [`src/boardgamerules/domain/validators.py:54`](src/boardgamerules/domain/validators.py#L54)
- **Why & How**: Validating storage keys inside the domain model prevents malicious inputs like "../../etc/passwd", null bytes, or absolute paths from reaching filesystem or blob adapters.

### Canonical Identifier Normalization
- **Location**: [`src/boardgamerules/domain/validators.py:68`](src/boardgamerules/domain/validators.py#L68)
- **Why & How**: Because both MongoDB (document metadata) and Qdrant (vector chunk filters) partition data by game_id, normalizing arbitrary user input ("Settlers of Catan!") into a deterministic slug ("settlers-of-catan") prevents duplicate silos and cache misses across databases.
